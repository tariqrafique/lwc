# D-0239 / D-0241: napi error position only under `location`

`bot/js-d0239` **828d7f9** on main **5e2d886**, pid **834b11163fc62de972b08a757f3f8d1cd8941fcf**.
Cite D-0239, D-0241, AB-L0076. Local gates, PROVISIONAL. Not landed.

Harness main **a93494b** (AB-L0076) already reads location ONLY from `ne.location`; `NapiCompileError` has no `line` / `column` / `name` and no `err.errors` message fallbacks. This change deletes the matching own keys from the napi serialization so the seam matches upstream `CompilerError` / `CompilerAggregateError`.

### Design

- `JsCompileError` drops `name`, `line`, and `column`. Own keys are now `message` plus the shipped subset of `code` / `filename` / `location` / `errors` / `level` / `url`.
- `compiler_error` sets `location` only (still own-but-`undefined` via `Either::B` when unknown).
- `aggregate` no longer sets own `name: "AggregateError"`. Harness builds `new AggregateError(subs, message)` itself, so the prototype name is correct without an own key.
- `unnormalized` no longer mirrors `line` / `column` onto the JS object.
- `UnnormalizedError` drops its `line` / `column` fields. `From<CompileError>` takes `location` only from the first diagnostic (AB-L0080: no bare line/column fold).

`JsAggregateEntry.name` is unchanged in this change (sub-entry fixture value `"Error"`; harness `errors[]` type does not read it). `CompileError.line` / `column` stay in lwc-shared for `normalize_to_compiler_error`.
