### Design

`localize` now takes the pre-print `&Allocator` + `&mut Program` and:

1. Collects used helpers by walking `StaticMemberExpression` nodes whose object is the identifier `babelHelpers` and whose property is a known helper name (AST shape, not span or text). That includes oxc transformer-inserted nodes with a 0-span.
2. Closes the dependency set from recorded member spans on the static helper-body templates (same shape, pinned next to each template; verified by `tests/helper_templates.rs`, which parses `void (<body>);` and compares spans).
3. Allocates module-local names with `Uids::generate` (unchanged babel `generateUid` rules).
4. Rewrites each matching member on the Program to an `Identifier` of that local name. The replacement keeps the member's span so codegen `with_source_text` does not invent a second token stream; identification never uses that span.
5. Builds the prelude from the original template source with those AST spans rewritten (including the `ID` identifier in `classPrivateFieldLooseKey`). Emission format is unchanged (`function {local}{rest}` / `var {local} = {body}`), so the prelude text stays byte-identical.

`post_codegen_edits` only remaps version-stamp inserts through the codegen map and inserts the prelude at 0. It no longer searches printed JS. The `/// SHIM(D-0262 P1 post_codegen_edits, expires D-0265)` comment and its `harness/shim-registry.tsv` row are removed in this commit (`Cross-Lane: harness`). Remaining JS rows: `pass_with`, `unforgeables`, `async_functions` (plus the template AB-D0004 row). Shim gate: tags=4 rows=4.

Helper-body `refs` / `subst` text scans of `babelHelpers.` are gone. `BABELHELPERS_FIND` is now empty; a text `.find` / `.replace` / `.match_indices` of `babelHelpers.` anywhere under `crates/lwc-js/src` fails R8b (orphan rows also fail). `PARSE_SITES` is unchanged: this step adds no parse of helper templates at compile time and does not touch residuals (1) or (3).

The `contains()` prefilters that belong to *other* passes (`...` for rest/spread, `async` for async-to-generator, `location`/`top` for unforgeables) stay with those passes (Arch carried them to the D-0265 exit). This pass had no printed-JS `contains("babelHelpers")` prefilter to remove.

### LWS async reprint

`async_functions` still replaces the stamp list after reprinting. Helper members that exist before that reprint (object-spread, private-field helpers) must still be `babelHelpers.*` members on the Program async parses, because a second `localize` only sees remaining helper members and emits a prelude in `HELPERS` table order (private-field helpers sit *after* the async helpers). Concatenating two preludes would reorder them.

So `transform_inner` defers `localize` when `enable_lightning_web_security_transforms && edited.contains("async")` — the same predicate `async_functions` uses on its input, evaluated on the span-edited source before the first print. In that case `async_functions` is the single localize of the post-async Program. Otherwise this print is final and `localize` runs here. That `contains("async")` is not a new printed-JS prefilter for this pass.
