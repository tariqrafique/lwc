### Design (AB-L0075)

There is no defer predicate. `localize` always runs on the pre-print Program:

1. Collects used helpers by walking `StaticMemberExpression` nodes whose object is the identifier `babelHelpers` and whose property is a known helper name (AST shape, not span or text). That includes oxc transformer-inserted nodes with a 0-span.
2. Closes the dependency set from recorded member spans on the static helper-body templates (verified by `tests/helper_templates.rs`).
3. Allocates module-local names with `Uids::generate`, rewrites matching members to those identifiers, and returns a `LocalizedHelpers` set (helper name → local name, plus the reserved `id` counter when `classPrivateFieldLooseKey` is used). It does **not** emit a prelude.

`async_functions` parses printed JS (D-0264 residual 3, unchanged) and runs `localize` on that Program. Members rewritten in step 1 are already local idents, so this pass only picks up `babelHelpers.*` members the async transform introduced.

`helpers::prelude` then emits **one** prelude from the union of both sets, in `HELPERS` table order. Deps are closed in `localize`; `prelude` never mints a name. `post_codegen_edits` only remaps version-stamp inserts; the caller inserts the prelude at 0 after any LWS unforgeables remap / async reprint, so the insert is in the final printed coordinates.

The `/// SHIM(D-0262 P1 post_codegen_edits, expires D-0265)` comment and its `harness/shim-registry.tsv` row were removed in `f79ea1b` (`Cross-Lane: harness`). Remaining JS rows: `pass_with`, `unforgeables`, `async_functions` (plus the template AB-D0004 row). Shim gate: tags=4 rows=4.

Helper-body `refs` / `subst` text scans of `babelHelpers.` are gone. `BABELHELPERS_FIND` is empty; a text `.find` / `.replace` / `.match_indices` of `babelHelpers.` anywhere under `crates/lwc-js/src` fails R8b. `PARSE_SITES` is unchanged.

### Why AB-L0075 was needed

`f79ea1b` deferred `localize` when `enable_lightning_web_security_transforms && edited.contains("async")`, copying `async_functions`' cheap-exit onto different text. Arch's repro

```
export default class A extends LightningElement { #p = 1 /* async */ + 2; get x(){ return this.#p /* async */; } }
```

made `edited.contains("async")` true (the word lives in comments). Codegen drops those comments, so `async_functions` cheap-exited, `localize` never ran, and the output had bare `babelHelpers.classPrivateFieldLooseKey` / `LooseBase` and no prelude (a runtime `ReferenceError`).

The required shape has no second copy of that predicate. The cheap exit lives in `lower.rs::source_has_async` (`src.contains("async")`) and is called only from `async_functions`. `apply_async_functions` no longer repeats it. `async_predicate_lives_in_one_fn_called_from_one_place` fails if a second `.contains("async")` appears in any `crates/lwc-js/src` function, or if `source_has_async` is called from anywhere but `async_functions`.

### r3 (AB-L0075 r2 merge condition)

Arch approved `20660a8` with one merge condition (notes 6a24823): every dead fallback in `helpers::prelude` had to go. Planted panics in those branches were never reached. Removed:

- the `close_deps` re-run inside `prelude`
- the `names.push((n, uids.generate(n)))` regeneration branch
- `Uids::from_reserved` and `Uids::remember` (nothing else called them; deleted)
- the `loose_key_id.is_none()` reserve of `id`

`prelude` is now a pure union of the localize sets in `HELPERS` order. A helper whose local ident is empty, or a `classPrivateFieldLooseKey` with no `loose_key_id`, is an internal error (`assert!` / `expect` in every profile). `close_deps` still runs once, in `localize`, so every needed helper already has a local ident before `prelude` sees the sets.

`prelude_is_a_pure_union_and_does_not_generate_uids` scans the `prelude` function body and fails if it mentions `Uids`, `from_reserved`, `remember`, `close_deps`, `.generate(`, or `.reserve(`.
